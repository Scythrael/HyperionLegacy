# Hotfix 0.13.11.2: prestige previews (plan and carry note)

Route: hotfix off production (`origin/main` at `e06c039`, 0.13.11.1), branch `hotfix/0.13.11.2`. Display only:
no rule, balance or save change (SAVE_VERSION untouched, no goldens moved).

User intent (verbatim): "It's hard to tell if the actual weight of what these prestiges accomplishes changes."

## What ships

Each card on the minigame's Prestige tab gets a preview line right above its button, showing what resetting NOW
does to the multiplier that layer moves:

- Captain Prestige: "Captain Prestige now: xA to xB on the whole stack." (the Captain multiplier before and
  after, with the points this reset pays; Captain's Compound included because it is read from the engine).
- Fleet Prestige: "Fleet Prestige now: Augment xA to xB. Captain Points go back to 0, so the whole stack goes
  xC to xD." Decision: show BOTH. The Augment line is the layer's own weight; the whole-stack line is the net
  effect on production, because a Fleet also resets Captain Points and the stack can go DOWN right after a
  Fleet when the Captain bonus was large. Showing only Augment would hide that.
- Prestigeception: "Prestigeception now: Captain and Augment gains xA to xB. Captain and Augment Points go back
  to 0, so the whole stack goes xC to xD." With Lucid Dreaming owned, also "Dream Points speed the stack xE to
  xF." (User, 2026-10-26: YES, say the points go back to 0, like the Fleet line, with the stack before and
  after.)

When a layer pays nothing yet, the line is HIDDEN (not a threshold preview). Reason: the card already says
"Ready at", the button already reads "needs ...", and a threshold number would differ from what the player gets
once the climb passes the threshold; the live line only appears when it is true.

## How (no duplicated math)

`engine.ts` `prestigePreview(s, layer)` runs the real reset (`doCaptainMut` / `doFleetMut` /
`doPrestigeceptionMut` through `firePrestigeMut`) on a copy and returns `prestigeWeights` (captainMultiplier,
augmentMultiplier, prestigeMultiplier, gainMultiplier, dreamSpeedMultiplier) before and after, or null when the
reset would not fire. The overlay computes it only while the Prestige tab is open.

Numbers print with `format.ts` `formatMultiplier`: formatSecret everywhere except 10 to 1,000, where it keeps three
significant figures (formatSecret prints 12.4 as "12", which made a small change read "x12 to x12").

Example values (engine-built states): mid game with autos, Captain x3.98 to x4.80, Fleet Augment x2.79 to x2.92
with the whole stack x11.1 to x2.92, Prestigeception hidden; past e1,000,000, Prestigeception gains x31.5 to
x32.7 with the whole stack x646 to x1; past Starfall (Lucid Dreaming 10), gains x61.3 to x62.1, the whole stack
x119K to x12.9, and stack speed x12.8 to x12.9.

Tests (`src/lib/secret/prestigePreview.test.ts`): before and after equal the engine's multipliers on the state
before and after a real `doCaptain` / `doFleet` / `doPrestigeception`, the input is untouched, and null exactly
when the real call does nothing. Edge cases: zero points on each layer, every Captain's Compound level, every
Lucid Dreaming level, Fleet with the stack falling and rising, Fleet after the Skill Point cutoff, and engine-built
states past e1,000,000 and past Starfall.
