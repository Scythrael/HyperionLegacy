Colour-blind palettes

The game encodes state and rarity in colour: success / warning / danger and a 7-tier rarity ladder. Under red-green colour-blindness (~8% of men) several of those hues converge. This proposes a colour-blind-safe palette on the Okabe-Ito basis, and shows every role under a deuteranopia simulation so you can judge it on your screen.

Every block on this page marked DEUTERANOPIA SIM is filtered live to approximate how a red-green-colour-blind viewer sees it. Compare the SIM columns — that's where "current" fails and "safe" holds.

04 How it's built — and why it seeds the skin system

  • Today the theme blocks only swap the accent. [data-theme] overrides --color-accent (+ borders / muted text / starfield) but NOT --color-success/warning/danger or the rarity ladder — so a colour-blind option has to make those palette-driven.
  • That groundwork IS the bucketized palette layer your skin system needs. Once semantic + rarity colours are tokens a palette can override, every future palette — colour-blind, and later the Pride / Trans / gradient sets — slots in as one more registry entry. Build once, right.
  • A few palettes, as registry entries: Deuteranopia/Protanopia-safe (the Okabe-Ito set shown here — one palette covers both red-green types) and a Tritanopia-safe variant (blue-yellow), added the same way. More can follow without a rework.
  • Where they live: Settings › UI › Accessibility (a palette selector), sitting alongside the theme picker rather than replacing it.
  • Rarity backstop: rarity keeps its text label, so even the untouched hardcoded tiers (stellar/radiant/constellar) stay legible; remapping them to the safe set is a bonus, not a blocker.

Okabe-Ito safe values — accent #56B4E9, success #009E73, warning #E69F00, danger #D55E00; rarity: augmented #009E73, stellar #56B4E9, radiant #CC79A7, luminous #E69F00, constellar #F0E442.
