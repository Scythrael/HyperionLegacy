# Research tech trees (future idea, user 2026-11-17)

Status: IDEA, unscheduled ("For the future, of course"). The 0.14.0 Research tab gets search and filter now
(docs/superpowers/specs/2026-11-17-research-filter-and-crew-standard-issue-design.md); the user will ask players whether
they would prefer a tech tree, and leans toward the tree.

## The user's words (verbatim)

"So I have an idea for research trees. Something similar to how we handle specs. So we choose the type of research.
Ship classes, ship systems, crew equipment, components, etc. Then when you select those, it opens up into a tech tree.
Something similar to the radial option we already have. But then we have a tree of initial requirements and such that
then allow for th enext options to unlock, etc etc. But we will want to consider how we want to handle this because we
don't want to timegate too much. So I think we'd have multiple trees with multiple starting points, effectively. We'd
need to find a proper way to display this. Something intuitive. But I believe the tech tree approach is going to be the
best way to do it overall. For the future, of course."

Earlier the same day: "I can ask the players if they'd find another option better to use, like a tech tree similar to
our talent trees. I'm starting to lean toward that a bit."

## The shape, as the user described it

- Pick a research TYPE first, the way a spec is picked. Types named so far: ship classes, ship systems, crew equipment,
  components ("etc.": the list is open).
- Picking a type opens its TECH TREE, presented like the existing radial option (the talent-tree radial).
- Nodes have requirements: initial projects unlock the next options.
- Anti-goal: do not timegate too much. Answer the user gave: several trees, each with several starting points, so a
  player is never stuck behind one long chain.
- Must be intuitive to read; the display is an open design problem.

## Open questions for when it is picked up (not decided)

- Which release; and whether it replaces the list or sits beside it (the 0.14.0 filter stays useful either way).
- The type list: does it follow the existing research families (Propulsion, Defense, Weapons, Systems, Field, Hull
  Design, Materials, Sensors) or the user's groups (ship classes, ship systems, crew equipment, components)?
- What an edge means: a prerequisite project only, or also lab tier, materials or relic discovery (today's gates).
- How undiscovered relic projects appear in a tree without spoiling them.
- Phone layout for a radial tree.
- Needs a mockup before any build (feedback: visual UI needs a mockup).
