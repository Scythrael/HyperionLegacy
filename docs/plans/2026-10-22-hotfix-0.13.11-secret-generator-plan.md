> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Settings > Codes sub-tab with an Enter Code window (gift code box plus a 12-press combo pad) that opens a standalone, offline-capable, huge-number generator game over the blurred, still-running main game.

**Architecture:** The secret game is a pure TypeScript engine under `src/lib/secret/` with its own state, its own versioned localStorage key and its own 1-second ticker; it never reads or writes main `GameState`, never runs inside `economyTick`, and never touches the main loop. App.svelte only gains the sub-tab, the two mounts, the runtime start, the Delete Save / Debug reset wipe and dev-only Debug fast-forward buttons.

**Tech Stack:** Svelte 5 (legacy, non-runes syntax as in the rest of the repo), TypeScript, break_infinity.js `Decimal`, Vitest.

**Spec:** `docs/plans/2026-10-22-hotfix-0.13.11-secret-generator-design.md` (APPROVED "as is") and its capture doc `docs/plans/2026-10-22-hotfix-0.13.11-secret-generator-capture.md` (answers 1 to 24). ## Review Focus

The five failure modes most likely to bite a real player, each pinned by a test in the owning task:

1. **A long absence pays less than staying open would have** (overnight, a weekend, a 30-day break). Pinned in Task 6: `long gaps never pay less than live` runs 1-second live steps against the coarse catch-up from four representative states (early manual, mid game with autos, just after a Prestigeception, past the finale) for gaps of 6 h + 1 s, 10 h, 2 days and 7 days, and asserts best Ore, every prestige currency, prestige counts, Overclock level and owned counts are each at least live and best Ore is within a sane bound above.
2. **Opening the game after a month away freezes the tab.** Pinned in Task 6: `a 30-day gap stays fast` asserts the step count is at most `MAX_CATCHUP_STEPS` and the wall time is under 1.5 s on the test machine (the measured time is recorded in the results section).
3. **A small constant tweak silently breaks the planned playtime.** Pinned in Task 7: `steady player pacing` asserts first Captain Prestige in 30 to 60 minutes, the finale in 3 to 5 days, e1,000,000 in 26 to 34 days, and that best Ore still rises in the week after e1,000,000.
4. **The combo fires or fails on the wrong keys** (Numpad Enter, Left Shift, held-key repeats, typing in the code field, a wrong press of Up). Pinned in Task 2: `comboKeyForCode` and `advanceCombo` tests cover every listed key plus repeat and the "wrong Up restarts at 1" rule; Task 10 keeps the key handler a thin call into these.
5. **The secret save leaks into or survives the main save** (Delete Save leaves milestones behind, blocked storage crashes, a corrupt secret save breaks load). Pinned in Task 3 (`garbage or foreign JSON loads a fresh game`, `blocked storage still runs`, `uses its own key`) and Task 12 (`resetSave wipes the secret save` source-wiring test).

## Design decisions the builder made (within "exact constants and formulas", design section 11)

These are recorded so reviewers can check them against the structure the design fixes.

- **Overclock price is time-based.** One level costs `OC_SECONDS` seconds of the last step's Ore income divided by the prestige multiplier, flat within one purchase, never below a geometric floor (`OC_FLOOR_BASE x OC_FLOOR_STEP^level`, which stops a "buy Overclock right after a reset" exploit). Result: in-run growth of the Ore exponent is linear in time and its rate scales with the prestige multiplier, which is what makes (a) days-long pacing robust instead of knife-edge, and (b) catch-up step-size neutral, so long gaps can be coarse and still fair. Still "a repeatable Ore purchase, x1.125 to all production per level, rising cost".
- **Fleet Prestige and Prestigeception pay from the best Ore since the last Fleet / Prestigeception**, not only the current Captain run (auto Captain resets the run constantly, so "current run" would make Fleet gains depend on when you happened to look).
- **Tier unlocks are permanent** once earned (lifetime Fleet count) [PROPOSAL]; Prestigeception resets Captain Points, Augment Points and the current Fleet count, keeps skills, unspent Skill Points and unlocked tiers.
- **Three extra skills** (design allows up to four of the same kinds) [PROPOSAL]: Auto Overclock, Auto Fleet Prestige, Auto Prestigeception. Every auto skill has an on/off switch; each auto prestige has a player-set target "when the gain is at least X% of what you have" (default 100%).
- **Diminishing returns from the finale:** the engine keeps a raw Ore value; everything the player sees or that pays out (Ore display, costs display, prestige gains, milestones, goal bar) uses an effective exponent `L_eff = g(log10(rawOre))`, identity up to 777,777 and a concave power curve above it (`g(x) = 777,777 + S((1 + (x - 777,777)/S)^BETA - 1)/BETA`). It never stops rising and has no cap.
- **Catch-up:** gaps up to `EXACT_BOUND_SECONDS` = 6 h run as 1-second steps through the very same function live play calls every second (exact by construction). Longer gaps use `n = min(MAX_COARSE_STEPS, ceil(gap / MIN_COARSE_DT))` equal coarse steps followed by a `COARSE_TAIL_SECONDS` fine tail; tests prove they never pay less than live.
- **Dev hooks:** the existing build-time `DEV_MODE` gate (Debug tab; true on local `.env.local` and on preview/staging builds, false on production). The code has no `?dev` URL switch (it was removed 2026-07-11, see App.svelte), so the hooks live in the Debug tab.

- [ ] **Step 3: Implement.** Production over `dt` integrates the linear cascade exactly for constant multipliers:

```text
for target m = 0..n-1 (0 is Ore, m is owned[m-1]):
  acc = 0; prod = 1
  for j = 1..n-m: prod *= rho[m+j-1] * dt / j; acc += x[m+j] * prod
Ore gain with Overdrive = (acc/dt)^1.05 * dt; lastIncome = Ore gain / dt
```
  where `rho[k] = baseRate[k] x tenBonus^floor(bought[k]/10) x 1.125^overclock x prestigeMultiplier`.
