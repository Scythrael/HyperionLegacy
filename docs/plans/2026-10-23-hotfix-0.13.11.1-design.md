## 1. Combo window

- Replace the 12 separate slots with ONE segmented strip at the top of the combo area: 12 equal-width segments; each
  correct press fills the next segment with its symbol: arrows as SVG glyphs, A and B inside circles, SEL and STA
  inside squares (labels "SEL" and "STA"). Wrong press still clears silently. One row at 375 px.
- The combo now only UNLOCKS. First success: opens the minigame (as today) and records it as unlocked; the code window
  shows a short message naming where it lives now. Any later success: does NOT open it; shows "You've already found
  this one. It lives under the Minigames button now." [PROPOSAL wording, match the mockup tone].

## 2. Gift codes

- First real code: `SUPERDUPERLEET` grants 1,337 credits to the main game, once per account (per save until 0.14.1
  online). Message: "Code redeemed. +1,337 credits added to your fleet." Re-entering: "This code has been redeemed on
  this account." From the third consecutive re-entry of an already-redeemed code: add one random line from the 40
  approved lines in `docs/plans/2026-10-23-code-redeemed-joke-lines.md` (all approved by the user), never the same line
  twice in a row, and TRACK which lines this account has seen.
- Achievement "Endless Greed" (default name; the user may pick another of the three in that file) when all 40 lines
  have been seen; shows the achievement popup (section 5).
- Storage: redeemed codes, seen-line ids and the Endless Greed flag live in the MAIN save (account-level), as OPTIONAL
  fields with safe defaults, no SAVE_VERSION bump (prod is SAVE_VERSION 54, feat 70: the fields must merge cleanly into
  feat and round-trip on both). Grant credits through the normal do* handler pattern (pure fn, same-ref guard, state =
  next, pushLog, doSave). Do not keep codes in plain text in the client if a cheap hash comparison works (for example a
  SHA-256 of the normalized code), but correctness first; codes are case-insensitive and ignore spaces and dashes.
- Any unlock (code or combo) shows a short message in the code window saying where to go.

## 3. Header button block (replaces the gear button where it lives today)

- Before any minigame is unlocked: a Help [?] button filling the top half of the space and Settings as a half-height
  horizontal bar on the bottom half. After the first minigame unlock: Help becomes a square (top-left), the Minigames
  button a square to its right, Settings stays the half-height bar below. (A future fourth button would make a 2x2;
  not now.)
- Help opens the existing Help center (later: the 0.15.0 redesigned one). Minigames opens a small list of unlocked
  minigames with Play buttons (one entry today: Hyperion Legacy v0.0000001a, with a one-line status). Settings opens
  the System modal as the gear does today.
- Must work on desktop and 375 px (touch targets >= 36 px except the half-height bar, which must still be easy to tap:
  full width of the block, at least 18 px tall, and the whole bar clickable), keyboard and screen reader labels, SVG
  glyphs only (a controller glyph for Minigames in icons.ts + ICON_SEMANTICS, reviewed at 16/28/56 px).

## 4. Minigame panel changes

- Main view: remove the goal bar, the "This run" bar and the per-row "makes X" lines. The freed space stays EMPTY (the
  user has plans). Keep the joke flavor line under each generator name. The center list scrolls inside the panel so
  the whole panel fits one screen (desktop and mobile).
- Header right: Stats button, then [?] Help, then close.
- New tab order: Generators, Upgrades, Prestige, Skills, Milestones.
- Upgrades tab: Overclock as a generator-style row (flavor line, level, Buy 1, Buy 10, Max). At e1,000,000 Ore four
  upgrades unlock, each with a level cap shown as "X / Y" once unlocked (user-approved exception to D23): Overclock
  Overclocker (each Overclock level counts more), Tenfold Tuner (each ten bonus doubles a little harder), Captain's
  Compound (more Captain and Augment Points per prestige), Lucid Dreaming (Dream Points hit harder). Their numbers are
  [PROVISIONAL] and set by the pacing sim. Before unlock, locked rows read "???" (name, flavor, everything), as do
  locked generators and locked milestones. On the first visit to the Upgrades tab after unlocking, a one-time message:
  "Congratulations, you unlocked the overclock overclocker! Kidding. Horses are extinct in the future, so there are
  none left to beat for this joke." (user copy, verbatim).
- Stats view (Stats button): goal progress (to the next Ore goal), This run, most Ore ever, most of each generator
  (owned peak per tier, kept through every prestige), highest Overclock, prestige counts, points, milestones reached
  (X of Y visible), time played, first found date. Must present well at 375 px (two columns or one).
- Help view: plain-language rules (the stack and what each generator makes, the ten bonus, Overclock and the
  upgrades, the three prestiges, skills, milestones, time away) with the same humor as the main interface.

## 5. Milestones and the achievement popup

- Ore goal milestones: e1,000, e100,000, e777,777 (the finale, special unlock), e1,000,000 (long achievement),
  e10,000,000 (new final stop; reward: the Starfall theme). Keep the other existing milestones. Milestones are HIDDEN
  ("???") until reachable: a milestone appears only once the previous Ore goal is reached (and non-Ore milestones once
  their system is visible).
- Popup on every milestone reached: "Achievement obtained: <name>", the requirement line, optional flavor text, and
  the reward line in green. It slides in, fades after about 4 seconds or on tap/click, stacks or queues if several land
  at once (for example after offline catch-up), respects reduced motion, and is announced politely to screen readers.
  It shows inside the minigame when open, and over the main game when a milestone lands while the overlay is closed.
  This is the small-scale prototype of the future main-game achievements system: build it as a reusable component.

## 6. Pacing

- Everything up to e1,000,000 stays exactly as shipped in 0.13.11 (first Captain Prestige ~45 min, finale e777,777
  ~3 to 5 days, e1,000,000 ~a month for the steady player): the pacing sim must reproduce those bands unchanged.
- After e1,000,000, the four upgrades carry a steady player to e10,000,000 in about 6 months (pin a band, for example
  150 to 210 days). Growth after e10,000,000 may continue but slows hard; nothing new unlocks. Re-run the robustness
  check (check-in times shifted). Offline parity rules from 0.13.11 still hold (exact up to the bound, never less
  beyond).

## 7. The Starfall theme (the e10,000,000 prize)

- A whole-game theme STYLE layered over the player's chosen accent color: option D "wash plus shine" from the theme
  mockup and the reference image: panels and buttons get a diagonal gradient from the current accent (top left) into
  purple (right), translucent at today's alpha levels; headings and progress bars get the accent-to-purple gradient;
  primary buttons a soft sheen. Implement it as theme tokens (for example a `data-style="starfall"` attribute on the
  root plus token overrides in app.css), not per-component hacks, so future styles (A, B, C) can be added as a
  dropdown later. Check contrast stays readable (AA) on every accent theme and in the color-blind palette.
- Unlocked when the minigame reaches e10,000,000 (the flag lives in the secret save and is mirrored to an account-level
  flag in the main save so a Delete Save wipes it with everything else). Selectable in Settings > UI next to the color
  themes once unlocked; device-side preference like the other visual settings; hidden before unlock.
- Dev-only: a Debug button to grant the unlock for testing (compile-time DEV_MODE like the other Debug rows).

## 8. Constraints

All constraints of the base design still apply: the main game's economy, offline catch-up and goldens unchanged
(beyond the credit grant, the new optional save fields and the header block); text rules (no em dashes, no "--"
substitutes, US English, install never fit, player-facing objective never task); SVG glyphs only; Svelte 5 in the
existing style; the secret game's errors never reach the main game; gates `npx vitest run --maxWorkers=4
--testTimeout=60000`, `npm run check`, `npx vite build`.
