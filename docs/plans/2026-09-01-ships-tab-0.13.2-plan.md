# Ships Tab Redesign (0.13.2) — Build Plan

Companion to `2026-09-01-ships-tab-0.13.2-design.md`. Branch `feat/ships-tab-0.13.2`.

**Method:** subagent-driven-development per unit (implementer → spec review → code-quality review), branch-direct commits, one-fix-one-commit. **Every unit gates green before commit:** `npm run check` (0 errors), `npx vitest run` (full suite), `npx vitest run -t "parit"` (exactly 101). Pure-UI units keep parity trivially; the point is to prove no regression. Mockup-approved design is fixed; do not re-litigate layout mid-build.

**Ordering principle:** relocate-then-enhance. Get Ships living in its own tab with today's behavior intact (Units 1-2, low risk, shippable), then layer the roster, equip board, and install flow (Units 3-5), then dots + polish (6-7), then QA (8). Each unit leaves the branch green and demoable.

---

### Unit 1 — Nav: the 6th tab + SVG icons
- **Goal:** `TabKey += "ships"`; render the 6 bottom-nav buttons in order Home · Crew · Ships · Facilities · Logistics · Ops, each with an inline SVG icon; relabel the Facilities button (drop nothing else); add a `{#if activeTab === "ships"}` content branch (placeholder that renders the existing ships block in Unit 2).
- **Files:** `App.svelte` nav markup `9607-9613`, `TabKey` `773`, nav CSS `10593-10622`. Optionally lift the 6 tabs to a `NAV_TABS` data array + loop (recommended, kills six near-duplicate buttons and makes the dot in Unit 6 trivial).
- **Approach:** match the inline-SVG idiom at `App.svelte:9596` (`viewBox="0 0 24 24"`, `fill/stroke="currentColor"`, `aria-hidden`). Keep `.nav-tab` `flex:1`. Preserve `activeTab` behavior for the existing 5.
- **Gate + review.** No behavior change beyond the new (empty) tab.

### Unit 2 — Relocate ships out of Logistics (behavior-preserving)
- **Goal:** move the Ships grid→detail block into the Ships tab with today's behavior byte-for-byte, then remove it from Logistics.
- **Files:** move `App.svelte:7044-7248` under the new `activeTab === "ships"` branch; rename `logisticsShipsView` → `shipsView` and relocate it + `selectedShipId` + the vanished-hull guard (`1031-1047`); remove `"ships"` from `LOGISTICS_TABS` (`1052`) and the `activeLogisticsTab` union (`1017`) + its `onSelect` cast (`7040`); Logistics keeps default `"materials"`.
- **Gate + review.** Verify: Logistics no longer shows Ships and lands on Materials; the Ships tab shows the roster grid + can open a ship detail; the guard still snaps back if a hull vanishes. Still opens the existing `ShipSystemsPanel` modal (redesigned in Unit 4).

### Unit 3 — Roster upgrade
- **Goal:** the sortable/favoritable roster. Sort control (Attention default; Name / Class / Rating / Status), favorites (localStorage set, pinned group), class grouping, search box, filter chips, `damaged` indicator + attention flags (empty required combat slot / damaged / unassigned), compact rows, whole-row tap.
- **Files:** the relocated roster grid in `App.svelte`; a new **pure** `src/lib/game/shipRoster.ts` (build the sorted/filtered/grouped view model + the per-ship attention predicate) + `shipRoster.test.ts`; a localStorage favorites helper (mirror `salvageConfirmPreference`).
- **Approach:** derive one compact model reactively; key rows by `ship.id`; attention predicate reuses existing fields (`ship.damaged`, `equippedFor` empty required combat slot, `assignedCaptainId === null`). Keep it cheap per tick.
- **Gate + review** (+ roster unit tests: sort orders, favorites pinning, class grouping, attention flags).

### Unit 4 — Equip view: Layout C loadout board
- **Goal:** replace the ship-detail / modal panel with the drill-down loadout board: hull identity tile (class + Battle Rating), groups Offense / Defense / Systems, Offense = auto-scaling 3-wide **weapon-tile grid**, Defense/Systems = rows; each slot/tile carries a **stable Swap/Install button**; empty required combat slot flagged; damaged banner + Repair; rename; Assign / Salvage as stable buttons; live readout via `computeCombatReadout`. **Tooltips display-only** (pass no action slot to `EquipmentTooltip`).
- **Files:** fold `ShipSystemsPanel.svelte` content into the drill-down (either refactor the panel to render inline, or migrate its markup into the Ships tab and retire the modal wiring at `App.svelte:9880-9901`). Reuse `equipment.ts` fns + `combatFit.ts` unchanged.
- **Approach:** the weapon grid renders `weaponHardpoints` cells (filled + empty), auto-reflowing; DO NOT re-derive stats (call the pure readout). Move the injected tooltip Install/Uninstall (`ShipSystemsPanel.svelte:1213-1239`) OUT to standalone buttons; the tooltip becomes hover/tap-for-info only.
- **Gate + review.** Verify install/uninstall still routes through `installSystem`/`uninstallSystem` → `fitEquipment`/`unfitEquipmentInstance`; damaged lock preserved; economy never-empty vs combat allow-empty preserved.

### Unit 5 — Install flow (INSTALLED banner + tile list + compare)
- **Goal:** tapping Swap/Install opens the flow: INSTALLED banner + equipped card; scrollable compatible-spare tile list (each tile shows net BR delta); Cancel. Compare: current-vs-candidate cards + per-stat deltas + net rating; **Install** commits, **Back** returns. Responsive: desktop = list + both cards in one pane (updates in place); mobile = drill.
- **Files:** new install-flow UI in the Ships tab; the **pure simulate-candidate helper** `src/lib/game/shipLoadout.ts` (§6 of design) + tests; lift the spare-pool compat query out of the old panel into a reusable function.
- **Approach:** preview via the helper reusing `shipToCombatant`/`battleRating`/`computeCombatReadout`; Install calls `fitEquipment`. Verify each candidate with `canFitEquipment` for enable/disable.
- **Gate + review** (+ helper test: previewed candidate readout == actual post-`fitEquipment` readout).

### Unit 6 — Nav attention dots
- **Goal:** an amber dot on any bottom-nav tab whose perspective has an actionable item; clears as resolved. Ships dot = any ship damaged / empty required combat slot / unassigned-with-orders-available. Reuse the Home dashboard's needs-you signal so the two never disagree.
- **Files:** a small per-tab predicate (lean on `buildHomeDashboard`/`shipRoster` outputs); the dot UI on the nav (trivial if Unit 1 used the `NAV_TABS` array); dot precedent `home-dot` `App.svelte:8913-8915`.
- **Gate + review.**

### Unit 7 — Responsive polish + display-only sweep + a11y
- **Goal:** final reflow tuning (no horizontal scroll at any width; loadout board + install pane collapse cleanly on phone); confirm NO action anywhere lives in a tooltip (sweep the ships surfaces); focus management + aria labels on the drill-down + install flow + nav; reduced-motion respected; copy uses INSTALL.
- **Gate + review** (holistic 3-lens pass here).
