Action Modal Standardization

One shared shell for every ACTION modal in the game: centered card on desktop, bottom sheet on mobile, always with a backdrop, a sticky header carrying the title + close, a scrolling body, and a sticky action footer. Approve the shell here; then it gets extracted into one component and every action modal is migrated to it (carefully, keeping each one's theme + reading correct).

Scope: install flow, confirm dialogs, and pickers migrate to this shell. Excluded: the Options gear popup (its own thing, standing exclusion). Focus is trapped inside (Escape + the header X + a backdrop tap all close). Extracted from the 0.13.2 install-flow modal, which is the reference implementation.

What the shared component standardizes

  • Backdrop that dims the app and closes on tap (outside the dialog).
  • Placement: centered card on desktop, bottom sheet flush to the bottom on mobile (drag-handle affordance), from one breakpoint, not per-modal CSS.
  • Sticky header: uppercase mono title on the left, a close X on the right, always reachable even when the body scrolls.
  • Scrolling body with consistent padding + gap, so long content (compare tables, long pick lists) scrolls inside the sheet, never the page.
  • Sticky footer for actions: a ghost Cancel on the left of the primary action; destructive actions use the danger color.
  • Focus trap + Escape close baked in (the shared focusTrap action), so every migrated modal traps + restores focus identically.
  • Excluded by rule: the Options gear popup keeps its own treatment.

If the shell reads right, the plan is: extract this into one ActionModal component (props: title, close handler, optional footer slot), then migrate each action modal (install, confirms, pickers) onto it one at a time, gating each, so any single migration is easy to review + revert.
