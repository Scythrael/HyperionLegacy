## 1. Intent

A gift-and-giveaway front door in Settings, and behind it an easter egg: a version of the game's very first prototype
(the July 2026 Generator Stack, commit `66687f3`) comes back, expanded, funny, and with huge numbers. It is a
standalone side game: nothing it does touches the fleet in 0.13.11. Its milestones are recorded now so a later patch
can pay main-game rewards with back pay. It should feel like a treat for players, not a chore: short and sweet with an
end (a special unlock in a few days), a long achievement for the devoted (about a month), and room to grow later.

## 2. Goals, non-goals, anti-goals

Goals
- A new Settings sub-tab with an "Enter code" button opening a window with two ways in: a gift code box with Redeem,
  and a "Combo input" button that opens a 12-press combo pad.
- The combo Up, Up, Down, Down, Left, Right, Left, Right, B, A, Select, Start opens the secret game over the blurred,
  still-running main game.
- The secret game: four original generators plus four new ones in a cascade, three prestige layers, skills with
  auto-buyers, milestones, a finale at e777,777 Ore and a long achievement at e1,000,000 Ore, humor throughout.
- Runs while closed and while the game is closed (offline progress), like the main game.

Non-goals (0.13.11)
- No real gift codes ship; every code is "not recognized" (answer 10).
- No main-game rewards from the secret game yet (answer 8: record now, pay later).
- No content past e1,000,000 (answer 16: future content starts there).
- No shortcut back into the secret game: the combo is the only way in, every time (answer 9).

Anti-goals (it fails even if it works)
- Anything that touches or risks the main save, its migrations, offline parity or its numbers.
- Spoiling the secret: no player-facing text anywhere names the combo or says a secret exists (patch note wording is
  the user's call, section 9).
- Stress or chores: no timers that punish, no "you lost progress"; auto-buyers arrive early enough that late play is
  watching numbers go up, not clicking Max (build ease-of-use, sell peace).
- Hard caps past the end: past e1,000,000 growth continues on diminishing returns, never a wall (D23).

## 4. The Enter Code window

A modal over the System modal (reuse the app's existing modal pattern and focus handling), title ENTER CODE, close X
and Esc.
- GIFT CODE: a text field (uppercase display, monospace) and "Redeem". 0.13.11 has an empty code table: a non-empty
  code answers "That code isn't recognized."; an empty field answers "Type a code first." Build the redeem path as a
  real seam for later patches: a pure `redeemCode(code)` against a code table (empty now) that returns a result kind;
  no reward plumbing is needed yet. Do not log codes anywhere.
- OR divider, then "Combo input" (full width). It expands the combo area in place:
  - 12 slots. Each correct press lights the next slot with its glyph (arrow SVGs, B, A, SEL, STA). A wrong press
    clears the slots silently (if the wrong press is Up it counts as a fresh first press). No error text.
  - The on-screen pad on every device: a D-pad (Up, Left, Right, Down), SELECT and START buttons, round B and A
    buttons, plus a hint line "Keyboard: arrows, B A, Right Shift, Enter". Pad buttons are real buttons with
    aria-labels.
  - Keyboard while the combo area is open and focus is not in the code field: `event.code` ArrowUp, ArrowDown,
    ArrowLeft, ArrowRight, KeyB, KeyA, ShiftRight (Select), Enter (Start, the main Enter only; NumpadEnter does not
    count, ShiftLeft does not count and does not clear). Any other key clears. preventDefault on combo keys so arrows
    do not scroll.
  - The window never shows or hints at the sequence.
- On the 12th correct press: close the Enter Code window and the System modal, and open the secret game overlay.

## 6. The game

All numbers below are starting points. The builder tunes them with the pacing simulation (section 7); the structure
is fixed.

Numbers: `break_infinity.js` Decimal (already a dependency). Display: the main `formatNumber` style suffixes K to Oc,
then scientific `1.23e45`; exponents of 1,000 and up get thousands separators (`4.21e1,284`, `e777,777`). Write one
formatter for the secret game in its own module so the main formatter is untouched.

Generators (cascade, answer 11). Tier I makes Ore; every higher tier makes the tier below it, at a rate per second.
- I Mining Laser, II Refinery, III Fabricator, IV Synthesizer (the originals), V Fusion Forge, VI Graviton Press,
  VII Quantum Loom, VIII Singularity Engine (mockup names).
- Each tier has "owned" (bought plus produced) and "bought". Output = owned x base rate x multipliers. Every 10 bought
  doubles that tier's output ("the ten bonus", factor 2, raised by a skill). Costs are in Ore and rise by a factor per
  10 bought, steeper per tier. Buy 1, Buy 10 (to the next ten), Max.
- Tiers I to IV are open from the start (I costs 10 Ore and the player starts with 10 Ore), V and VI unlock at
  Fleet Prestige 1 and 2, VII at 3, VIII at 6 (mockup said VII at 3, VIII at 6; V and VI are my call).
- Overclock: a repeatable Ore purchase, x1.125 to all production per level, rising cost.

Prestige layers (answers 12, 15, 17, 21). Each layer resets everything below it.
- Captain Prestige (small reset), available from 1e60 Ore: resets Ore, generators and Overclock; pays Captain Points
  from a concave formula of the run's peak Ore; each Captain Point multiplies all generators (the multiplier grows
  with points on a curve, never capped).
- Fleet Prestige (big reset), at 1.8e308 Ore: also resets Captain Points; pays Augment Points (multiply everything,
  stack with Captain Points) and 1 Skill Point; the Fleet Prestige count unlocks tiers V to VIII.
- Prestigeception (third layer, "a prestige for your prestige, while you prestige"): above Fleet Prestige, at a
  threshold the builder sets (suggested around e10,000 Ore). Resets everything below, Skills kept. Pays Dream Points;
  each Dream Point multiplies the Captain Points and Augment Points earned per prestige (answer 21). It exists to
  make the numbers climb faster in the long run (answer 16).

Skills (Skill Points from Fleet Prestige; kept through Captain and Fleet Prestige; kept through Prestigeception): the
mockup's six plus room for a few more: Auto-buy I to IV, Auto-buy V to VIII (needs the first), Auto Captain Prestige
(at a target the player sets), Ten Bonus x2.2, Head Start (begin resets with 1e10 Ore), Overdrive (Ore production to a
small power, about ^1.05). The builder may add up to four more of the same kinds (for example Auto Fleet Prestige,
Auto Overclock) if the pacing needs them; mark any addition [PROPOSAL] in the report.

Milestones (finite, about 10 to 12, funny names, answer 18). Each records the real date it was reached and shows
"Reward recorded" when reached or "Reward arrives in a future update" before. They include at least: first Captain
Prestige, a googol of Ore (1e100), first Fleet Prestige, first Prestigeception, build a Singularity Engine, the
finale (e777,777 Ore, the special unlock), and the long achievement (e1,000,000 Ore). The two named goals are
flagged as achievements in the record so the later patch can treat them specially (answer 16).

The finale and after.
- Reaching e777,777 Ore the first time opens a one-time celebration screen inside the overlay with a funny send-off,
  records the special unlock, and play continues.
- Reaching e1,000,000 Ore records the long achievement and shows a second short celebration; a line says more is
  coming later.
- From the finale on (user, builder check Q1: "Slow down from the finale"): diminishing returns begin at e777,777.
  Every source of growth softens on a concave curve above e777,777 (for example the Ore exponent is compressed above
  it), so the finale arrives in days and the climb to e1,000,000 is the long, month-long stretch. The number never
  stops, it slows; no hard cap (D23). Past e1,000,000 the softening keeps going.

Offline (answer 6). The game runs while the overlay is closed and while the browser is closed.
- The secret game's state carries its own `lastTickAt` wall-clock stamp. On app load and whenever the overlay
  opens, it catches up the elapsed real time; while the app is open it advances in the background (it can ride the
  main loop's poll, but in its own state, never inside `economyTick`).
- Catch-up vs live (user, builder check Q2: "Exact short, fair long"): one fixed step function. Gaps up to a bound
  of several hours (the builder picks it, at least 6 hours) run in the same 1-second steps live play uses, so they
  match live exactly (test: same state, Decimal-equal). Longer gaps use coarser fixed steps and are guaranteed never
  to pay less than live would have (test: for a range of long gaps, catch-up Ore, prestige currencies and owned
  counts are each at least the live result, and within a sane bound above it). Auto-buyers and auto-prestige act
  inside steps. Catch-up must stay fast at load (it runs on the main thread beside the main game's own catch-up):
  bound the step count and measure a 30-day gap in a test.
- No offline cap (answer 6 was "Always runs").

Storage. Its own versioned save under its own localStorage key (for example `hl_secret_v0`), read and written through
the existing guarded storage helpers, JSON with Decimals as strings. It is never part of the main save, its
SAVE_VERSION or its migrations. Blocked storage means the game still runs for the session. The player's Delete Save
(Settings > Save Data, the type-DELETE confirm that runs `resetSave()` then `clearSave()`) ALSO deletes the secret
save (user, builder check Q3: "Yes, wipe it too"), so recorded milestones never carry into a fresh save; this is the
one sanctioned touch of the main delete path, and the confirm text does not mention the secret. Debug "Reset save"
does the same (it is a delete). Save Data export/import does not include it in 0.13.11 (my call; revisit when
rewards arrive).

## 7. Pacing (the builder's tuning job)

A pure simulation harness (tests, not shipped UI) plays a "steady player": buys Max on every tier every few minutes
before auto-buyers, takes each prestige when its gain is worth it by a simple rule, buys skills in a fixed order, and
checks in a few times a day with offline gaps between. Targets (answer 20):
- First Captain Prestige within the first session (about 30 to 60 minutes).
- Finale e777,777 Ore in about 3 to 5 days of real time for the steady player.
- e1,000,000 Ore in about a month (most of it on the diminishing-returns stretch after the finale).
Tests pin the simulated times to those bands so later tuning cannot silently break them. Keep the simulation fast
(coarse steps are fine there).

## 10. Constraints (project rules)

- Svelte 5 in the existing App.svelte style; the overlay and Enter Code window as their own components under
  `src/lib/`; the game engine as pure TypeScript modules under `src/lib/secret/` (or similar) with unit tests.
- SVG glyphs only (arrows, check, star, any new ones in `icons.ts` plus ICON_SEMANTICS, reviewed at 16, 28 and 56px);
  never emoji.
- No em dashes and no "--" anywhere in added lines; US English; player-facing text says "install" never "fit" and
  "objective" never "task".
- The main save, `economyTick`, offline catch-up and all existing goldens stay byte-identical: no main-game test
  changes except adding the sub-tab and the Delete Save hook.
- Gates: `npx vitest run --maxWorkers=4 --testTimeout=60000` green and `npm run check` 0 errors; `npx vite build`
  succeeds.
