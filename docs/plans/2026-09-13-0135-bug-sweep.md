# 0.13.5 bug sweep — 2026-09-13

Scope: a **targeted** sweep of the highest-probability bug surfaces after the header rebuild, not a line-by-line audit of the ~6,000 changed lines vs prod. Focus was on the classes of bug that have actually bitten this release (event-forwarding on components, dangling DOM references after renames, reduced-motion gaps) plus the riskiest changed logic. Everything below was verified against source, not assumed.

Branch `feat/presentation-0.13.5`; prod (main) is 0.13.3.1. Gates green throughout: check 0 errors (2 expected RadialWeb a11y warnings), 2739 tests, parity 101, build clean.

---

## Squashed this session (all on staging)

1. **Header popup dismissal referenced a deleted class** — `commit 861c583`. `handleCurrencyOutsidePointer` still tested `.closest(".currency-chip-wrap")`, which the rebuild removed. With it gone, the window-level pointerdown no longer recognized the new Currency/Fuel button or its popup, so a re-tap dismissed-then-reopened the popup and a tap *inside* the popup closed it. Now matches `.tb-pop-wrap` (wraps both button and popup). Verified in-browser: opens, and an outside tap dismisses cleanly. **This was a real interaction bug introduced by the rebuild.**

2. **Header EXP/CRAFT bars ignored `prefers-reduced-motion`** — `commit 258ac51`. The new `.tb-bar > i` fill animates its width over a tick as XP/craft accrue, the same slide the release's own reduced-motion rule disables on `.research-bar-fill`/`.tick-bar-fill`, but it was left out of that rule. Added it; the bar now steps instead of sweeps for reduced-motion users. Minor, accessibility.

(The header rebuild itself — the primary task — is `commit b215c74`.)

## Verified clean (checked, no bug found)

- **Toggle event wiring** — all 4 `<Toggle>` call sites use `on:change` + `e.detail` + a save call. The forwarding bug that made the tick-bar toggle dead is not present anywhere else.
- **Auto-salvage union→filter rework** (`salvage.ts`) — the critical "nothing ticked = take NOTHING, never EVERYTHING" guard (`if (!autoSalvageHasAnyRule(rules)) return []`) is present; axis filtering and the duplicates-narrows-further logic are correct and heavily tested.
- **Idle-captain routing** — `IDLE_JUMP_BY_SPEC` is an exhaustive `Record<ShipSpec, JumpTarget>` over the 4-value union, compile-guarded.
- **Operations Overview tab** — groups gathering vs patrol captains correctly, has an empty state, reuses the existing in-progress card snippets. No double-listing (one mission per captain).
- **Confirmation-level ladder** — the settings write through to the real gate variables (`refineConfirmEnabled`, `autoSalvageBaselineWarningEnabled`) that already gate their dialogs (used at App.svelte:2187/5794 and :5308). Not a "setting that does nothing".
- **No stray `console.*`/`debugger`** in shipping (non-test) source. No other stale `.closest()`/`querySelector` DOM lookups (only `.cq-list`, which still exists).

## Not deeply audited — suggested QA focus

- **Header on real mobile widths.** I verified structure and both states (compact/expanded) via the accessibility tree at desktop width, but could not screenshot the wrapping layout (the browser pane can't composite while it's not on-screen). The mobile reflow relies on flex `order` + wrap; **worth an eyes-on pass on a phone**: portrait + name + gear on row one, Currency/Fuel on row two, the stat rows below when expanded, bars not stretching edge-to-edge.
- **Currency/Fuel popup on touch** — re-tapping the button does not close the popup (open-only; dismiss is tap-outside/Escape). This matches the old chip behavior exactly, but the new caret (⌄) visually implies toggle. Decide if you want tap-to-toggle; it's a deliberate call, not a bug.
- The wider 0.13.4/0.13.5 logic (`tick.ts`, `berths.ts`, `laneAllocation`, `model.ts` migrations) carries its own new test files and was out of scope for this header-centric sweep.
