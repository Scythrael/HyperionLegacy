# Hotfix 0.13.10: progress keeps full pace in background tabs and after sleep

Branch hotfix/0.13.10-hidden-tab (worktree ../fleet-admiral-hotfix), off main b93d067 (production 0.13.9).
Commits d7a2734 (fix), 18982ff (APP_VERSION + patch note). Under review 2026-10-16.

Bug (production): the live loop granted one economy cycle per 100 ms poll and discarded overshoot; throttled hidden
tabs (Chrome 1 Hz, then once a minute after 5 minutes), sleep and jitter lost game time (about 36% over 10 hidden
minutes, about 90% over an hour, 1 tick for a 1-hour sleep, about 5% even visible); the hidden tab's autosave stamped
last_saved_at = Date.now(), so offline catch-up never recovered it.

User decisions (2026-10-16):
- "Hotfix 0.13.10 now (Recommended)"; "Same as offline (Recommended)" for the return summary.
- Recap threshold: "2 minutes. If the tab is idle in teh background, or minimized, or something to that end, we want to
  make sure that progress is not lost." (AWAY_SUMMARY_MIN_SECONDS = 120.) The goal: NO progress lost in any case.
- Last-minute loss when a hidden tab closes: "Yes, if review says safe (Recommended)": include the save-timestamp fix
  in the hotfix if the reviewer confirms it is safe.
Flow: review, fixes, push to staging (`git push origin hotfix/0.13.10-hidden-tab:staging`) for the user to try, user
promotes to main (pre-flight `git log main ^hotfix/0.13.10-hidden-tab`), then merge main into feat/crew-0.14.0.
