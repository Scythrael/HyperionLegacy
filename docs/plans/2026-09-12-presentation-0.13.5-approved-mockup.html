Why it is a chevron

The header holds the portrait and now the gear. If the whole bar expanded on tap, those two would be swallowed by it. A dedicated chevron is the only version where all three targets can coexist.

The gear

A square peer control beside the portrait, not a badge on it. Same size as the portrait so it reads as an equal, not a decoration. It opens System on the Settings tab.

Compact keeps a bar

The EXP bar survives at 5px with the percentage beside it. A bar too short to read is decoration, so the number carries the precision and the bar carries the glance.

Crafting level

Amber, so it reads as a sibling of FA level rather than a duplicate of it. Expanded only on mobile; always visible on desktop.

Currency and Fuel buttons

Two buttons, not one. Fuel is not a currency, and there will be several of each, so one merged list would have mixed two kinds of thing under one wrong label.

Each shows its favourited total on the face and the full list in its popup. ★ marks what also appears in the header, which is the hook for the favourite-a-currency idea.

Decisions for section 01

  1. ✅ Compact keeps the EXP bar. Settled.
  2. ✅ Expanding pushes, taking vertical space from the main pane while open. Settled.
  3. ✅ Desktop two-up stays as drawn. Settled.
  4. ✅ The state is remembered per device. Settled.
  5. ✅ The Currency and Fuel popups are approved, including choosing which entries show on the header face.

The toggle

Square corners, 44×22 with a 16px knob. Off is a dim grey knob on the left; on slides right and glows in the current theme via the accent token, so it recolours with the theme and any future skin.

It is a real role="switch" with aria-checked and a focus ring. A styled div would be a control a keyboard or screen-reader user cannot operate.

“Greyed a bit” uses the dim text token, not the disabled token. An off toggle is fully interactive, and the disabled token means “you cannot use this”.

The ? help

A floating tooltip now, not a block that pushes rows down. Hover opens it on a pointer; tap opens it on touch and tapping away closes it, so it is never hover-only on the platform that has no hover.

It opens BELOW-LEFT, anchored to the row, so it never covers the control it describes. That is the one real cost of floating over pushing, and placement is the fix.

The “your values are kept when you switch a rule off” note lives in the ? text, per your call — that is exactly what the ? is for.

Quality: a question

Shown as checkboxes to match the rarity row. Today it is a threshold dropdown, because “off” and “Q0 and below” are different things a checkbox cannot tell apart. Checkboxes are a save change plus migration.

Decisions for section 02

  1. ✅ Quality stays the threshold dropdown for now, pending your rework of how quality is expressed. No save migration in 0.13.5.
  2. ✅ Glow strength is right. Settled.
  3. ✅ Tighter gaps, now 6px to match the Recently Completed rhythm. One number to change if it reads too tight in place.
  4. ✅ Floating tooltip, dismissed by moving off on desktop or tapping away on mobile. Settled.
  5. ✅ 6px is right. Settled.
  6. ✅ The tooltip flips ABOVE the row when it would otherwise fall below the fold. A help bubble you have to scroll to find is worse than none, because you do not know it is there.

The one new field

Entry source does not exist yet. Everything else maps to a real field. Worth adding regardless: the board currently makes you infer the facility from a glyph.

Tap already meant something

These rows already navigate. So the chevron expands and the row keeps its jump, with a labelled button in the expanded view as well. Losing the one-tap jump would remove a feature that exists to save taps.

The compact line

Leads with clock time in your own timezone, in a fixed-width column so the dot and the summary start at the same x on every row. That alignment is most of why a stack of rows reads as tidy.

Format is time · Verb: Item × N. The “over mm:ss” moved to the expanded view: duration is rarely what you scan for, and dropping it is what buys the alignment.

Age (“20h ago”) survives in the expanded When line, so the “what did I miss” answer is not lost, only demoted.

Decisions for section 03

  1. ✅ Clock time, in the player's own timezone. Settled.
  2. ✅ The item and amount are on the compact line, the duration is not. Settled.
  3. ✅ Independent, open as many as you like. Settled.
  4. ✅ A “show more history” toggle, off by default, keeping the current limit until switched on. Built into the mock above.
  5. ✅ 68px time column is right. Settled.
  6. ✅ Symmetric spacing around the history toggle: a divider and equal breathing room above AND below it once expanded, so the toggle sits between two matched gaps rather than hugging the rows beneath it.
