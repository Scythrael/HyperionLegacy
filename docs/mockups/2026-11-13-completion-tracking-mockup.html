Completion tracking: per system and per body

Hyperion Legacy 0.14.0, for sign-off before the build (docs/plans/2026-11-13-completion-tracking-design.md). Your 2026-11-13 answers, drawn as decided: what counts is "Bodies + objectives": each body scanned plus each objective cleared on it, weighted evenly; 100% means every body charted and every objective done. Shown on the Expedition Console (each system and body row), the telescope map (a small ring or tag on charted systems) and the Survey Log / Archive (every visited system with its %). At 100%: a badge and a ledger entry, no stat reward. The chat-event ledger stays hidden until chat (no screen in 0.14.0). S2-65 (completion gating relic rarity) is not built.

Sample save: the real Tier II system OR-9359 (1,320 ly, from the engine's own candidate draw for this homeworld) is under way on Kestrel; ten other systems, also real draws for this homeworld (Wolf 359, 51 Pegasi, Betelgeuse, Eagle Nebula, LB-, OR-, PE-, SA-, SC- catalog systems), are in the Archive. Their body and objective counts are sample numbers inside each tier's real body range. Amber dashed boxes are questions for you; amber dashed outlines mark what is new on a screen.

The same system can come backEach candidate list is drawn fresh: a famous system rolls 1 in 12 per slot and catalog numbers (0001 to 9999) can repeat, with new bodies from the new run's seed. Question 2.tierCandidateSystems, FAMOUS_SYSTEM_ONE_IN, CATALOG_NUMBER_MAX.

The rule drawn everywhere below (Question 1, option A, as answered): % = (bodies scanned + objectives done) / (bodies + objectives found so far), rounded to a whole percent. A body not yet scanned counts as one unit (its scan). Example: 3 bodies, 2 scanned with 5 objectives found, 3 of them done: (2 + 3) / (3 + 5) = 63%.

6. Notes for the build

  • The chat-event ledger stays hidden (your answer): reaching 100% appends one ledger event (system, tier, when), written at the claim; no screen, no count, no log view in 0.14.0. It joins the ledger's first event, a relic set completed.
  • A new per-system record is the one save change: written at claim (and at abandon if Question 11 is A) with the system's id and name, tier, bearing and distance, body count, bodies scanned, objectives found, done and skipped, and when. Optional key, appended, no save bump; the % is always derived from these counts, never stored as a number.
  • One pure function computes the % for a live run, a held system and a record, so the console, the map and the Archive can never disagree; goldens first, deterministic, offline equals live by construction.
  • No reward and no grind pressure: nothing reads the % except these three displays and the ledger.
  • Player text says "objective" everywhere, Roman numerals for tiers, US English.
