# Combat 1.0 / 0.13.0 pre-debut bug log

Collected before the prod promotion. Two sources: **(A) user-reported** during device testing, and **(B) the multi-agent code audit** (findings appended when that workflow completes). Nothing here is fixed yet by policy: gather everything, triage, agree a plan, THEN fix, before 0.13.0 ships.

Severity: critical (data loss / crash / softlock) > high (wrong result, reachable) > medium (visible defect, workaround exists) > low (cosmetic / edge).

## A. User-reported (device testing, 2026-08-26)

### BUG-U1 — Crafted combat gear invisible in the Logistics -> Ship Equipment warehouse tab
- **Severity:** medium (display only; items are SAFE and still installable via the ship-systems equip picker, so no data loss).
- **Scope:** weapons, shield emitters, hull plating, AND drone pods all missing. Economy systems (cargo bay / FTL / reactor / prospecting rig) show correctly.
- **Root cause (confirmed):** `BAY_SLOT_ORDER` (App.svelte:2822) = `["cargoBay","ftlDrive","reactorCore","specUtility"]` — the four ECONOMY slots only. `baySystemGroups` groups spares by that list, so any piece whose slotType is `weapon` / `shieldEmitters` / `hullPlating` / `droneBay` is filtered out of the display. The warehouse tab predates combat gear and never had the combat slots added.
- **Suggested fix:** add the four combat slots to `BAY_SLOT_ORDER` (order TBD). Then VERIFY: (1) the Salvage Bay (same `baySystemGroups`) salvages/destroys crafted combat gear correctly (weapon/drone blueprints carry recipes, so material refund should work — confirm salvageEquipment does not assume equipmentOutput); (2) combat Standard-Issue baselines that were uninstalled (pooled) render + destroy cleanly here.

### BUG-U2 — Stale "Weapons — coming soon" reserved placeholder
- **Severity:** low.
- **Detail:** the Logistics warehouse shows a reserved "Finished Goods" family row (`LOGISTICS_RESERVED_GOODS`, App.svelte ~6887) marking Weapons / Modules / Consumables as "coming soon (combat)". Weapons are now craftable + real, so the Weapons marker is stale/contradictory.
- **Suggested fix:** drop "Weapons" from the reserved list (Modules + Consumables stay reserved). Ties to BUG-U1 (weapons should show as real gear once BAY_SLOT_ORDER includes them).

### BALANCE-U3 — Per-hull crafted-defense crossover (NOT a bug; 0.16.0 structural item)
- **Severity:** n/a (balance, deferred to 0.16.0).
- **Detail:** the Standard-Issue defensive floor is PER-HULL (freighter shield 200 / plating 400; carrier shield 500 / plating **880**). The interim `CRAFTED_DEFENSE_IMPLICIT_MULT = 10` (47e81b9) makes crafted defense reachable on small/mid hulls and carrier SHIELDS (crossover ~iLvl 33), but carrier PLATING needs ~iLvl 48 to cross 880, ABOVE the tier-2 iLevel cap of 40, so crafted plating stays underwater on the carrier (observed: crafted 90-110 hullStrength vs SI 880). A single global multiplier cannot serve a 200-floor and an 880-floor hull at once. This is concrete evidence for the already-logged 0.16.0 structural item (per-hull crossover + per-tier iLevel caps + flat SI-floor magnitudes). Confirmed NOT a regression: SI floors are the hulls' authored SHIP_TYPES values (model.ts:767/879), untouched by any recent change.

## B. Multi-agent code audit findings

_Pending — appended when the preflight audit workflow (15 area-auditors + adversarial verification) completes._

### LEAD-U4 — Verify the ship-construction armor-seeding path (user hypothesis)
- **Status:** investigation lead (user wondered if ship construction is affecting crafted armor stats).
- **Clarification:** two separate armor sources — SI plating (880) is seeded at SHIP CONSTRUCTION (installMissingCombatBaselines / seedCombatStandardIssueForShip, = hull's authored hullStrength, correct); the crafted 90-110 plates are FABRICATOR output (iLevel-scaled, the BALANCE-U3 issue), not construction. They are not coupled.
- **Covered by audit:** the `model-logic` auditor reads generateCombatStandardIssue; the `tick-second-half` auditor reads installMissingCombatBaselines. If ship construction mis-seeds combat baselines (wrong hullStrength, duplicate/missing pieces, wrong slot), it should surface there. Re-check when audit findings land.

### BUG-U5 — Cross-hull Standard-Issue defense transfer exploit (DESIGN, high)
- **Severity:** HIGH (reachable balance exploit; not a crash/loss, but breaks combat balance).
- **Exploit:** SI combat baselines carry the SOURCE hull's full authored defense (Unit 1.4 behavior-preserving fold: SI plating hullStrength = hullIntegrity - frameHp, per-hull; carrier = 880, freighter = 400). Combat slots are allow-empty with POOLABLE baselines (Unit 1.8a), and canFitEquipment does not hull-lock a baseline. So: build a carrier -> uninstall its 880 plating (or 500 shield) -> install on a freighter -> that freighter now fields 980 effective hull (frame 100 + 880) vs its authored 500. Any multi-hull player can migrate the strongest SI defense onto a weak/favored hull. Shields identical.
- **Reachable:** yes, once the player has >1 hull type (carrier needs its hull blueprint; destroyer 480 -> freighter 400 is already an upgrade with just the two starter-ish hulls).
- **NOT a regression from the 2026-08-26 session:** combat baselines were poolable/transferable since Unit 1.8a; this session's allow-empty work was on ECONOMY slots. Pre-existing design hole, newly spotted.
- **Fix is ARCHITECTURAL (not a tuning knob):** the root tension is SI baselines being BOTH per-hull-magnitude AND freely transferable. Options: (a) HULL-RELATIVE SI defense — an SI plating/emitter yields the HOST hull's authored value, computed at shipToCombatant fold time, never a baked source-hull value (kills the exploit, keeps "SI = this hull's default"); (b) INTRINSIC hull defense — the hull's default defense lives on the hull, the SI "item" is a pure "no crafted gear installed" placeholder with no transferable magnitude; (c) HULL-LOCK SI baselines so they cannot install on a different hull type. (a)/(b) are cleanest. Decide during triage; likely lands with the 0.16.0 combat-defense rework or sooner if judged a debut blocker.
