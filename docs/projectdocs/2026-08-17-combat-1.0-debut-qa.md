# Combat 1.0 Debut: QA Sheet

**Branch:** `feat/combat-0.13.0` (staging / devpreview) targeting the prod debut.
**What shipped:** combat is now gear-driven. Weapons, shield emitters, hull plating, and drone pods are craftable and installable ship systems; every ship gets a free Standard-Issue combat set; a dispatch blocker requires weapons + shield + plating installed; Battle Rating and Threat Assessment readouts sit on the patrol dispatch card; a tougher showcase patrol (Crimson-Reaver Warband) makes hull choice, crafted gear, and drones matter.

**How to use:** run each check on **desktop AND mobile** (the two columns of your device pass). Mark P (pass) / F (fail) / N (note). Anything under "Expected behaviors" at the bottom is BY DESIGN, do not file it as a bug. Gate status at hand-off: 0 check errors, 1770 tests, offline==live parity 101, migration 30 to 35 probe-verified clean.

## A. Load and migration (highest risk: existing player saves)

- [ ] **A1.** Load an EXISTING pre-combat save (a 0.12.1 save if you have one). It loads with no error, and the economy/fleet state (captains, ships, resources, upgrades) is intact.
- [ ] **A2.** After A1, open each existing COMBAT hull's Ship Systems screen: it has a full Standard-Issue set (weapons on its hardpoints, a shield emitter, hull plating). Carriers also have a Standard-Issue drone pod in a bay.
- [ ] **A3.** Start a NEW game. A fresh combat hull arrives with its Standard-Issue combat set already installed (never unarmed).
- [ ] **A4.** Reload the page mid-session: state persists, no combat gear is lost or duplicated.

## B. Ship Systems and the install flow

- [ ] **B1.** Open Ship Systems on a combat hull: you see the weapon hardpoints strip (count matches the hull), a shield slot, a hull-plating slot, and (carrier only) a drone bays strip.
- [ ] **B2.** **Install flow is consistent for EVERY slot:** tap an empty slot / hardpoint / bay, the spare pool opens, tap a spare, it installs. Confirm this same tap-slot-then-tap-spare flow on a weapon hardpoint, the shield slot, the plating slot, and a carrier drone bay.
- [ ] **B3.** Uninstall: tap an installed combat piece, it uninstalls and the spare returns to the pool. A combat slot is left EMPTY on uninstall (this is intended; see E for why it is safe).
- [ ] **B4.** The combat readout on the panel updates live as you install/uninstall (hull, shield, weapon count, drone bays used).
- [ ] **B5.** Non-combat (economy) hulls do NOT show combat slots.
- [ ] **B6 (mobile).** The panel, hardpoints strip, drone-bay strip, and the spare-pool picker are all usable and readable on a phone. No clipping under the scrollbar.

## C. Crafting combat gear (the loop)

- [ ] **C1.** Research a combat blueprint (weapon / shield emitter / hull plating / drone pod) at the Research Lab, then fabricate it at the Fabricator. The finished piece lands in your spares.
- [ ] **C2.** The crafted piece is installable from the Ship Systems screen (it appears in the spare pool for its slot).
- [ ] **C3 (the 2.5a fix, verify explicitly).** Install a mid-to-high item-level crafted hull plating and shield emitter. The ship's hull max AND shield max go UP versus the Standard-Issue baseline, and Battle Rating rises. (Crafted DEFENSIVE gear used to be a downgrade until very high item level; it should now be an upgrade by mid item level.)

## D. Dispatch blocker

- [ ] **D1.** On a combat hull, uninstall all weapons (leave shield + plating). Try to dispatch a combat patrol: it is BLOCKED and the card names "no weapon."
- [ ] **D2.** Repeat for the shield emitter (blocked, "no shield emitter") and hull plating (blocked, "no hull plating").
- [ ] **D3.** Re-install the missing piece(s): the blocker clears and you can dispatch.

## E. Salvage guard (softlock protection)

Repeat spot-check for a spare SI shield/plating.
- [ ] **E2.** A CRAFTED combat piece IS still salvageable (select one, the Salvage action is offered and returns materials).
- [ ] **E3.** Confirm you cannot reach a state where a combat hull has an empty required slot with no free Standard-Issue piece anywhere to re-install.

## F. Battle Rating and Threat Assessment (dispatch card readouts)

- [ ] **F1.** The dispatch card for BOTH patrols shows a Battle Rating number and a Threat Assessment band.
- [ ] **F2.** The entry Crimson-Reaver Sweep reads a high band (Likely / Guaranteed Victory) for a geared combat hull.

## Expected behaviors (BY DESIGN, do not file as bugs)

- **11 of 13 combat status effects are live.** Inhibit (a drone-versus-drone attack-rate debuff, no clean weapon source yet) and the Overcharged Capacitors buff (waits for the 1.1 modules release) are intentionally deferred.
- **On the Warband, a Standard-Issue destroyer reads a hard band ("Extreme Challenge" / "Not Advised") on purpose.** The destroyer is a glass-cannon striker, not an anti-swarm platform; the whole point of the Threat Assessment is that hull choice, gear, and drones now matter. Battleship and carrier read mid-band.
- **The exact win percentage is intentionally hidden.** The named band is the read; the precise number is a deliberately deferred feature.
- **Combat numbers are a first pass.** On the single showcase patrol, a decent crafted set lifts every hull to Guaranteed quickly (a steep ramp), because there is one deliberately gentle-to-mid patrol. Deeper hull rosters, tougher content, and a smoother gear curve come in later updates and a dedicated balancing pass.
- **Guaranteed Victory requires zero losses across the whole forecast sample**, so it can never mislabel a fight you could actually lose.
