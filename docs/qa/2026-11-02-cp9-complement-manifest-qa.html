Builder notes (CP-9, 2026-11-02)

  1. Every buff shows. Buff2 and buff3 were never shown before; each group row, each notable card, the Graduate confirm and the manifest now list every buff as its own chip. Division buffs are green, the second-level exclusive buffs cyan with a diamond, and a held buff (Craft Duplicate Chance) dashed with "(Held for homeworld staffing)".
  2. Graduate keeps everything the same. One crew member of the group becomes a named notable assigned to the same ship, so the header, the division counts and the ship's buffs do not move (the notable is counted in place of the crew member). The name in the confirm is the name the notable gets.
  3. One mockup line was not true, so it changed. The cap message in the mockup said to send a notable back "to make room". Send back unassigns a notable but it still counts toward the fleet's 50 (your OC-8 answer: 50 fleet-wide, assigned or not), so the message reads "The fleet already has 50 notable crew" and the confirm says every notable counts, aboard a ship or not. See the open question below.
  4. The mockup's "Lt. Cmdr." name prefix is not built. The game has no short rank titles, so the confirm shows the name with the rank on its own line.
  5. Transfer shows, greyed. The selection bar's Transfer button is drawn as in the mockup but is disabled ("Crew transfer is not built yet") until CP-10 wires it.
  6. The manifest list scrolls inside its box so the pager under it stays in view, as the mockup draws it. Names are generated for the page in view only and never saved.
  7. No save step and no rule change. Graduate and Send back are the CP-8 engine, already tested; this slice only adds the screens, the App handlers and a division filter for the manifest (names unchanged by the filter).
  8. Open question (yours): at 50 notables there is no way to make room, since no action removes a notable. Should a notable ever be dismissable or retired, or is 50 a lifetime ceiling?
